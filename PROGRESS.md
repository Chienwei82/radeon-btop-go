# gputop-go — progress log

**Convention:** updated at the end of every milestone. Each entry records what
was built, what was *verified* (and on what), what was assumed, and what was
left undone. The verification ledger below separates measured properties from
designed-for ones. Phase numbers refer to `memory-bank/phases.md`.

**Status 2026-10-19:** Phases 0–4 complete; **v1.0.0 tagged**. The release
binary is static, 6,561,952 bytes, and was verified on an RX 6800 (host and
distroless with read-only `/sys`/`/proc`). The one measured target miss is the
`/proc` scan at ~800 processes (≈ 22 ms vs "well under 20 ms"), recorded below
rather than rounded away.

## Milestone 1 — data layer

**Scope:** Phase 1. `internal/model`, `internal/readers` (+ merge), `internal/sampler`,
`internal/config`, `internal/cli`; the headless path; the read-only guard; the
`--dump` parity gate; CI.

**Delivered**

- `internal/model` — value structs with pointer optionals (`nil` = N/A, never 0)
  and derived-value methods.
- `internal/readers` — `fsutil` (`(value, ok)` primitives), `metricsbin` +
  `metricsparse` (v1.0–v2.2, manual C-struct padding, sentinels → `nil`, unknown
  revision → sysfs fallback), `discovery`, `hwmon`, `dpm`, `throttle`, `pp`
  (SCPP + both overdrive eras), `procfs` (fdinfo dedup by
  `(drm-pdev, drm-client-id)` taking per-field **maximums**, cumulative-counter
  deltas, busiest-first sort), `merge` (`gpu_metrics ▸ device sysfs ▸ hwmon ▸ DPM`;
  clock ceiling always from the sysfs/DPM chain).
- `internal/sampler` — deadline-grid tick goroutine (no `time.Ticker`, so
  set-interval is immediate), bounded snapshot channel (cap 2, oldest dropped),
  history ring, bounded + de-duplicated warnings, `BlocksSource` seam
  (`disabledBlocks` until Phase 3).
- `internal/config` — YAML load/validate; unknown keys, bad types and malformed
  files become warnings plus defaults, never errors.
- `internal/cli` + `cmd/gputop` — `--dump` / `--devices` producing the
  reference's JSON shape, key order included; exit 3 when no card is present.
- **Read-only guard** — `internal/readers/readonly_test.go` parses every non-test
  file in the package and fails on filesystem mutators, write-capable opens
  (`os.OpenFile`/`syscall.Open` with write flags *or unresolvable flags*),
  `Write*`/`Truncate`/`Chmod` methods, `fmt.Fprint*` aimed off a standard stream,
  and shell redirects; process launchers are confined to `radeontop.go`. The
  scanner has its own positive and negative self-tests, so the guarantee does not
  rest on a check that cannot fail.
- **Parity gate** — `internal/cli/parity_test.go` compares the Go `--dump` against
  a golden produced by the **Python reference** on a committed synthetic
  sysfs/procfs tree (`internal/cli/testdata/parity/`), field for field, key order
  included. Regenerated by `scripts/parity_fixture.py`.
- **CI** — `.github/workflows/ci.yml` rebuilds the dev image and runs
  build → gofmt → vet → lint → test, plus the read-only guard and the parity gate
  as named steps.
- **Lint pinned** — `.golangci.yml` (v2 schema), `default: standard` plus
  `errorlint`, `misspell`, `unconvert`; `gofmt -s` in `formatters`.

**Verified**

- Gates green in the container (2026-10-13): `gofmt -l .` empty, `go vet ./...`
  clean, `golangci-lint run ./...` **0 issues**, `go test ./...` green.
- `--dump` parity against the reference on the committed fixture: equal after
  normalising only wall-clock/delta/user fields (see the test's doc comment).
- Real hardware: `./gputop --devices` found the RX 6800 (`0000:0c:00.0`,
  `0x73bf`), `--dump --interval 0.2` produced a full snapshot (`gpu_metrics v1.3`,
  three temperatures, ordered `voltages_mv`, PCIe Gen3 x16, SCPP table, a
  `llama-server` client at ~95 % compute, `process_visibility.partial = true`).

**Found and fixed (the gate earning its keep)**

- **ODC domain order**: `ParseODCVoltage` sorted domains alphabetically, so the
  dump emitted `mclk` before `sclk` while the reference emits them in file order.
  Fixed to first-seen order; `TestODCDomainsKeepFileOrder` pins it.
- **Redundant `int64(...)` conversions** in `internal/cli/dump.go` (the model's
  `Nanoseconds`/`Bytes` are aliases) — caught by `unconvert` once the linter set
  was pinned deliberately.
- **`scripts/podev.sh` flags-only invocation**: `podev.sh test -count=1` forwarded
  only the flag and `go test` fell back to the module root ("no Go files in
  /work"). The wrapper now appends `./...` when no argument names a package.

**Assumed**

- The committed fixture is generated from the reference checkout on this host;
  the BDF is `0000:ff:ff.7` (a PCI slot above the `1f` limit) so `boot_vga` is
  deterministically `false` on both sides and the golden does not depend on the
  machine that produced it.
- CI runs `podman` from the runner image; a full dev-image rebuild per run is
  accepted as the price of the toolchain living only in the container.

## Milestone 2 — optional panels and recording (panels + supervisor)

**Scope:** Phase 3. Supervised `radeontop`, power-profile/overdrive panels,
threshold alerts with flash, `--log` CSV/JSONL/zstd, `k` with confirmation,
atomic `[state]` persistence, full `--check`.

**Delivered so far**

- `internal/readers/radeontop.go` — the supervised per-block child: dump-line
  parser (by field name, never by position), argv builder, PCI bus extraction,
  both-streams failure classification, one drain goroutine per pipe, bounded
  restart, idempotent teardown, explicit pipe closing. Process launching stays
  confined to this file, which the read-only guard already asserts.
- `internal/sampler` — the pool implements `BlocksSource` behind the existing
  `WithBlocks` seam, so the tick loop is untouched. `internal/cli` +
  `cmd/gputop` wire it: `--blocks` / `--no-blocks` (mutually exclusive)
  override `blocks.enabled`, and `--dump` starts the panel only when it was
  asked for and waits for its first sample, so a dump still reproduces what the
  interface would draw.
- `internal/model/blocks.go` — `DisplayReading` + `GpuBlocks.DisplayRows()`:
  the presentation grouping (pipeline ▸ aux ▸ clocks, empty groups omitted) is
  model work, so the UI does not re-derive it.
- `internal/ui/blocks.go` — `BlocksPanel` / `BlocksHeading` / `blockRow`.
  `BlocksPanel(nil)` renders *one* explanatory line ("waiting for radeontop")
  rather than a column of `N/A`; a sample with no blocks says "no blocks
  reported"; a block at exactly zero still draws an empty bar with `0%` (a
  measurement, not an absence); a clock prints its frequency (`2,104 MHz`) and
  falls back to its percentage when radeontop reported none.
- `internal/ui/profile.go` — `PowerProfilePanel`: the read-only SCPP panel
  (active profile, the alternatives, the overdrive table with **its own unit
  per table**, and a closing "read-only" line naming where a change has to be
  made instead).
- `internal/ui/alerts.go` — `EvaluateAlerts` (judges **every** device, not the
  focused one), `AlertBorderColor` (accent when clear; alert/track alternating
  while crossed, a full cycle returning where it started) and `AlertNotice`.
  The event loop will own only the flash boolean.
- `internal/ui/layout.go` — the optional row: one threshold for both panels
  (`MinHeightForOptionalRow = 46`), absent entirely when there is nothing to
  say, cropped to the eight lines the reference measured, stacked below
  `2 * MinOptionalPanelWidth + 1` columns, and never allowed to cost a primary
  sensor reading (asserted by `TestOptionalRowNeverCostsAPrimarySensorReading`).
  The alert notice goes last on the status line (`LayoutInput.Alerts`).
- `internal/ui/panels.go` — `StatRowWidth`, so the blocks panel reserves its
  own (wider) label column; `StatRow` delegates to it.
- `internal/ui/format.go` — numbers are grouped in thousands
  (`groupNumber`/`groupThousands`), matching the reference's `f"{value:,}"`.

**Verified (inside the container, 2026-10-14)**

- `gofmt -l .` empty; `go vet ./...` clean; `golangci-lint run ./...` **0
  issues**; `go test ./...` green (8 packages); `go build ./...` exit 0.
- `go test -race` on the supervised-process tests: clean. Run with
  `CGO_ENABLED=1` in the dev image, which pins `CGO_ENABLED=0` for the
  deliverable.
- Repaired the committed tree: `internal/ui/keys.go` called
  `sampler.ClampInterval`, which was unexported at `3a2cc4b`, so
  `go build ./...` failed on `main`. The function is exported now and
  `clampInterval` delegates to it.
- The 100x40 golden screen was regenerated with `UPDATE_GOLDEN=1` passed into
  the container (the wrapper forwards arguments, not the environment) and the
  diff was read before it was kept: `2,200 MHz`, `1,000 MHz`, `2,400 rpm` —
  the thousand-grouping fix — plus the bar widths that follow from the shorter
  value text. Nothing else changed.

**Remaining in this milestone:** the rounding-semantics parity fix (below),
`--log` (CSV/JSONL/zstd), `k` with confirmation, atomic `[state]` persistence,
full `--check`, and the bubbletea event loop that carries them.

**Notes**

- radeontop splits its failure messages across both streams and the
  *actionable* one arrives last, so a failure is classified only after the
  stderr drain is joined. Classifying on stdout EOF alone tells a user their
  card is unsupported when the real answer is that they need root.
- The child is reaped only after both drains finish: Go closes a `StdoutPipe`
  inside `Wait`, so reaping earlier would race the readers.
- The width contract's last line is the layout's `crop`, not the panel. The
  optional row can hand the blocks panel as little as 30 columns, where
  `FitBarWidth`'s six-cell floor leaves a clock row one cell wider than the
  panel; the reference relies on the same widget crop (`overflow="crop"`), so
  that is parity. A first version of the test asserted "every row fits" at 30
  columns — a property the panel does not have — and was replaced by tests
  that sweep the widths where the contract holds and pin the overrun to the
  clock rows.
- **Open parity gap found while reviewing this milestone:** Python's `round()`
  is half-to-even while the port's idiom `int(x + 0.5)` is half-up, so a bar
  fill can differ by one cell at an exact `.5` boundary (`clamped=5, width=10`
  → reference 0 filled, port 1; `clamped=25, width=10` → 2 vs 3). Seven call
  sites (`ui/panels.go` ×2, `ui/format.go` `Bar`, `ui/devices.go` ×2,
  `ui/gradient.go` ramp index + RGB lerp). Neither test suite pins it — the
  reference asserts fill *ratios* with `pytest.approx(abs=0.02)`. Fix is one
  shared half-to-even helper plus a boundary-table test; scheduled as the next
  unit rather than changed inside this one.

## Milestone 3 — event loop, recording, signalling, state, full `--check`

**Scope:** Phase 3 completion. Built on `phase3-optional-panels` after the
supervised child (`407648a`) and the optional panels (`5a58f3b`).

**Delivered**

- `internal/model/round.go` — `RoundHalfEven`, the reference's `round()`
  semantics, shared by every bar fill, the ramp index, the RGB lerp and the
  PCIe link-speed parse. Boundary table in `round_test.go`; the UI keeps its
  own test that `Bar`, `StatRow` and the gradient all use it.
- `internal/sessionlog` — CSV and JSON Lines, zstd selected by the filename
  suffix; stable column set; absent readings are an empty cell (CSV) or null
  (JSON); the header is seeded from the file's size so a second session
  appends instead of writing a second header; write failures are values, not
  panics; `ReadLog` shares the suffix rule.
- `internal/control` — the signalling rules (refuse pid 1, kernel threads,
  gputop itself), the reversible default for an unknown signal name, and an
  injectable delivery function so the suite never sends a real signal.
- `internal/config.SaveState` — atomic `state:` write by editing the parsed
  YAML AST, so comments and key order survive; an unparseable document is
  refused rather than replaced; permissions are preserved, a new file is
  0600; directory fsync after the rename.
- `internal/check` system findings + `internal/cli.Check` + `--check [--json]`
  wiring: process-table ownership, the blocks panel (resolved but never run),
  the loaded amdgpu version, and a scriptable JSON shape.
- `internal/ui/app.go` — the bubbletea v2 model: snapshot wait, alert flash
  timer, help/filter/kill overlays, selection by identity, log thinning by
  `log.interval_s`, and one idempotent `Shutdown` that saves the state, closes
  the recording, and stops the sampler. It also runs after a SIGTERM.
- `internal/cli/tui.go` + `cmd/gputop` — the interface is the default mode;
  `--log`, `--no-color`; a signal asks the program to quit so the save still
  happens.
- Dependencies pinned: `charm.land/bubbletea/v2` v2.1.0,
  `charm.land/lipgloss/v2` v2.0.6 (the v2 modules declare `charm.land`, not
  `github.com/charmbracelet`), `github.com/klauspost/compress` v1.20.3.

**Verified (measured, 2026-10-19, container + host hardware)**

- Gates: `gofmt -l .` empty, `go vet ./...` clean, `golangci-lint run ./...`
  **0 issues**, `go test ./...` green (10 packages), `go build ./...` ok.
- Real hardware (RX 6800, kernel 7.0.0, amdgpu 6.19.4): `--check` reports the
  process table and 7/7 device metrics; `--check --json` parses as JSON with
  the documented keys; `--dump` still matches its golden.
- TUI under a pseudo-terminal (`script -qec`): renders the device, `--log`
  writes real CSV rows, and SIGTERM exits and writes `state:` at
  `$GPUTOP_STATE` with mode 0600 and two-space nesting.
- Rounding boundary table: `5% of width 10` fills 0 cells (was 1).
- Sessionlog: header-once, column count, empty-vs-zero, null-vs-absent,
  zstd magic + round trip, reopen/append, unopenable path, level range.

**Assumed / known gaps**

- `--check` did not list `/dev/dri` render nodes, which the reference does.
  Closed in Milestone 4 (`render nodes` in the text and JSON report).

## Milestone 4 — packaging and closure (`v1.0.0`)

**Scope:** Phase 4. A shippable release built with podman only, the last
parity gaps carried out of Phase 3, a complete verification ledger, hardware
runs and the v1 tag.

**Delivered**

- `internal/check` — `/dev/dri` render nodes are now part of the report, both
  as text (`sysfs`, `procfs`, `render nodes`) and in the JSON `environment`
  (`sysfs`, `procfs`, `render_nodes`). The dev root is derived from the DRM
  root exactly as the reference does; an unreadable directory is an absence.
- `cmd/gputop` — `-c`/`--config` and `-i`/`--interval` are real aliases,
  `--theme` validates against the five model themes and applies to the loaded
  config, and `--kind` rejects anything outside `auto|igpu|dgpu` (argparse
  parity). `version` is a variable stamped by the release stage with
  `-X main.version`. The test-only `run` wrapper was removed.
- `internal/readers/procfs.go` — the scan lists directories unsorted: nothing
  depends on order and sorting every `/proc/<pid>/fd` on every tick is pure
  cost. Behaviour is unchanged; the readers suite pins it.
- `packaging/man/gputop.1` — rewritten for the shipped feature set: every
  flag, the 30 key bindings, files, environment, exit status, examples and
  licence.
- `packaging/completions/{gputop.bash,gputop.zsh,gputop.fish}` — real
  completions with theme/kind values and file/directory completion, replacing
  the Phase 0 placeholders.
- `packaging/arch/PKGBUILD` — builds through podman (`makedepends=('podman')`),
  runs `check()`, and installs the binary, man page, three completions and
  licences.
- `LICENSE` (GPL-3.0-or-later) and `NOTICE` (upstream MIT copyright and text).
- `Containerfile` — the release stage stamps the version, disables VCS
  stamping, strips the binary and carries OCI labels; `.dockerignore` limits
  the context to source.
- `scripts/check_packaging.sh` — reads flags/themes/version from the source
  and fails on drift in the man page, completions, `PKGBUILD` or
  `Containerfile`; it also parses the bash completion and the PKGBUILD.
- `scripts/release.sh` — builds the release image, copies the static binary
  out of distroless, verifies the version, writes a deterministic tarball and
  `.sha256` under `dist/`.
- CI — a packaging step in the gates job and a `release` job that builds the
  artifact and verifies its checksum.
- Living docs — README install/cost/licence, SPEC §10 measured numbers and
  acceptance 15–16, DESIGN §7 packaging/release and the resolved risks.

**Verified (2026-10-19, container + RX 6800 host)**

- Gates: `gofmt -l .` empty, `go vet ./...` clean, `golangci-lint run ./...`
  **0 issues**, `go test ./...` green (10 packages), packaging check green
  (19 flags, 5 themes, version 1.0.0).
- Release binary: ELF 64-bit, statically linked, stripped,
  **6,561,952 bytes**; `--version` prints `gputop 1.0.0`.
- Clean-checkout release: `git archive 8e00695` (no `.git`, no `gputop`
  binary, no `memory-bank`) → `scripts/release.sh` built the same
  **6,561,952-byte** static binary; tarball **2,637,360 bytes**, checksum OK.
- Distroless image with `/sys`, `/proc` and `/dev/dri` mounted read-only:
  `--devices` found the RX 6800 (`0000:0c:00.0`, `0x73bf`); `--check` reported
  7/7 device metrics, `renderD128`, and the process table honestly hidden by

- **The SPEC §10 `/proc` target is not met**: ≈ 22 ms at ~800 processes versus

- CI's release job is new and has not run on GitHub (no remote configured).
- The 100x40 golden still has no exact rounding tie, and zstd append after a
  crash may lose the earlier frame (both inherited and recorded).

## Simplifying CI, and the two defects the cross-environment check exposed (2026-10-20)

**Scope:** post-v1 delivery work. Not a phase, and it does not move the version.
Branch `ci/simplify-release`.

**What changed**

1. **`release.yml` is one job, not two.** `artifacts` and `publish` handed files
   over through the artifact storage, and the fork case was the only reason for
   the split. That is a step condition, not a job boundary: publishing is now an
   `if` on a step inside a single `release` job, with no outputs to thread and no
   second checkout. A skipped *job* would never report and so could not be a
   required check; a skipped *step* costs nothing.
2. **The duplicate release job in `ci.yml` is gone.** It built the tarball and
   verified its checksum, which `release.yml` already does on the same event, so
   every pull request paid for the same build twice.
3. **Required checks are now `gates` and `release`** — one per workflow.

**Two defects the cross-environment check found**

Both were invisible while one machine built both artifacts, which is why "two
consecutive builds are byte-identical" was true and still misleading.

1. **The tarball carried the builder's umask.** `mkdir` and `cp` in
   `release.sh` take the umask and `tar` records the modes; `git archive`
   writes `0000664`/`0000775` under umask `0002` against `0644`/`0755` under
   `0022`. Rebuilding `bcc8fa7` here produced a tarball that differed from the
   published one in exactly **56 bytes**: every one of them a mode digit or the
   header checksum that follows from it, with the contents identical. Both
   scripts now pin the tree they stage (`find -type d` → 0755, `find -type f` →
   0644, executables → 0755).
2. **`SOURCE_DATE_EPOCH` made the AppImage build fail.** `build_appimage.sh`
   read the variable to choose the epoch and then passed `-all-time` to
   `mksquashfs`, which refuses both at once: *"SOURCE_DATE_EPOCH and command
   line options can't be used at the same time to set timestamp(s)"*. Exporting
   the reproducible-build convention therefore turned a correct build into a
   hard failure. The variable is now unset for that one call.

**Verified — the strong form**

- Rebuilt `bcc8fa7` from a `git archive` on this machine, with
  `SOURCE_DATE_EPOCH` exported, and got artifacts **byte-identical to the ones
  CI published**: tarball
  `27f39648ae68abc926aa82c2bad0e91b7bbf91808111c4429ec966a3aa5c68c2`, AppImage
  `3312e7811d30c7abb17492f288dede273a3cce2e8f6d597420b2ecfda899eaef`. The local
  `tar` 1.35 / `gzip` 1.14 against the runner's own set, so this is
  reproducibility **across environments**, not only across runs.
- The same source under `umask 0002` gives the same two hashes. Under the
  pre-fix `release.sh` the same umask gave
  `81c4f20063d1130e23ef657c1fa1ff40a2369035700370633e01d0c05c14fb18`, so the
  check is not vacuous: it fails on the old script and passes on the new one.
- `gofmt -l .` empty, `go vet` clean, `golangci-lint` 0 issues, `go test ./...`
  green (11 packages), `./scripts/check_packaging.sh` clean at `(version 1.1.0)`.
- `bash -n` on all four scripts; both workflows parse as YAML with one job each.

**Branches**

The seven phase and post-v1 branches were ancestors of `main` (ahead=0) and
